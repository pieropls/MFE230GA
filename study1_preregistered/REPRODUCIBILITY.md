# Reproducibility and data notes

## Inspecting completed work

No account, API key or paid model access is required to read reports, inspect figures, examine saved outputs or run `tools/verify_review_package.py`. The verifier uses Python's standard library. The 28 offline tests require the numerical packages recorded in `requirements-observed.txt`; no new package installation was performed for this export.

The recorded execution environment was Python 3.14.2 on macOS. Exact package versions appear in each study's `outputs/runtime.json`. `requirements-observed.txt` documents those versions; it is not a newly solved dependency lock. The model transport is specific to the audited Claude Code setup on macOS. Offline tests mock model requests and use synthetic fixtures.

## Evidence layout

Both studies keep the same layout under `outputs/`:

- `params.py`, `data.py`, `stats.py`, `agents.py`, `plots.py`, `run.ipynb`: exact completed-study source.
- `outputs/prereg_v0.json`, `outputs/prereg_amendments/`, `outputs/deviations.md`: original registration and recorded changes.
- `outputs/selected_features.json`, `outputs/research_summary.json`: research selection and development results.
- `outputs/sealed/initial/results.json`: full historical-test statistics.
- `outputs/sealed/initial/*_ledger.csv`, `*_weights.csv`, `*_scores.csv`, `*_ic.csv`: saved numerical outputs.
- `outputs/agents/`: candidates, prompts, reports, judgments, process summaries and transport evidence.
- `outputs/p1_review.*`, `outputs/p4_review.*`: audited concerns and their dispositions.
- `report/`: report and interaction log; team critique fields intentionally await the team.
- `work/research_runs/`: bounded request, control, event and response journals for the completed experimental calls.

## Export integrity versus original freeze

The source experiments remain unchanged locally. Each original `FREEZE.json` still describes the complete local experiment. This smaller export omits raw inputs and intermediate panels, so calling the study's original `verify_freeze()` on a clone will not pass. That is an intentional missing-input limitation, not permission to weaken the freeze check.

`package_manifest.json` records the source SHA-256 and exported SHA-256 of every copied file, plus omitted study files and their hashes. Frozen source and numeric outputs are copied exactly. Markdown links in review documents are converted to relative repository paths, and the test files' project locators are made relative. These presentation-only differences are individually recorded. Original project documents are unchanged. Historical delivery manifests and some audit records refer to original local paths/hashes; use the export manifest to verify this repository's presentation copies.

One exported mapping regression also replaces an accidental dependency on local source archives with tiny temporary date-only ZIP fixtures, following the existing source-manifest test. Its assertions are unchanged. This test-only correction is recorded in the export manifest; neither experiment's source or saved results changed.

## Data intentionally left out

- The original `230GA_Project_Data.zip`; SHA-256: `ce3c625da9baf3319d45af617aac9dbea6bdef219c2be6f4c9fe51b0193756a3`.
- Raw FRED/ALFRED and French source caches, intermediate Parquet panels, and bulky PPI discovery responses. Their provenance, dates, source URLs and hashes remain in the study manifests and input inventories.
- All raw Dewey/LinkUp and WRDS/Revelio downloads. These company sources failed the prespecified admission requirements and did not enter the final strategies. Teammates should obtain any restricted source through their own authorized institutional access.
- Credentials, login sessions, environment files, personal browser state, generated bytecode and abandoned technical-run directories. Sanitized audit status records only identify the authentication method/provider and subscription type; they contain no account identifier or credential.

The economic questions answered are Q1 (public labor information) and Q3 (agent search behavior). Q2 (company-data contribution) remains unanswered. Exact reproduction of data construction would require the pinned original source bytes, not simply current downloads, because historical source data can change. A full rerun also requires separate authorization and an explicit design; it would not create a new untouched holdout.
